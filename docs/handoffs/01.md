# Project 1: nested compositor foundation — handoff

Living document for Project 1. Updated in P1-T11.

## Context

Earlier sessions produced a libwayland-server skeleton (compositor, `wl_shell`,
seat with evdev input, X11/EGL window, launcher) that compiles but cannot show
a real client. This project replaced it with a proper xdg-shell nested
compositor that draws shm buffers on-screen, accepts X11 input, and reaps
launched children.

## Implementation notes

- **Protocol generation.** Three `custom_target`s in `meson.build` run
  `wayland-scanner` (`server-header`, `client-header`, `private-code`) on the
  XML from `pkg-config --variable=pkgdatadir wayland-protocols`; outputs land
  in `build/` and are never committed. Add further protocols the same way.
- **Resource ownership pattern.** Each `Mansion*` object is freed from its
  `wl_resource` destructor (fourth argument of `wl_resource_set_implementation`);
  `destroy` requests only call `wl_resource_destroy`. Cross-links
  (`xdg_surface` <-> `xdg_toplevel`, `wl_surface` <-> `xdg_surface`) are cleared
  by whichever side dies first, the wl_surface side through
  `wl_resource_add_destroy_listener`.
- **Configure handshake.** A toplevel is "mapped" only after the client acks a
  configure and commits a buffer. Order: `xdg_toplevel.configure(width, height,
  states)` first, then `xdg_surface.configure(serial)`. The serial comes from
  `wl_display_next_serial`; `ack_configure` currently stores it without
  validation.
- **Buffers.** `wl_shm_buffer_get(resource)` gives width/height/stride/format.
  Release the previous buffer after the new one is committed. The compositor
  uploads a pixel copy (`glTexImage2D`) so the buffer can be released immediately
  after upload.
- **Frame callbacks.** Collect `wl_surface.frame` callback resources per surface;
  after each render tick call `wl_callback_send_done(cb, tick)` and
  `wl_resource_destroy(cb)`. On surface destroy, fire remaining callbacks with
  `done(0)`.
- **Listeners.** libwayland listener structs must be static or otherwise
  outlive the resource.
- **Two roundtrips.** A client sees seat name/capabilities on the roundtrip
  after binding, not the one that delivered the global.
- **Headless GL.** `eglGetPlatformDisplayEXT(EGL_PLATFORM_SURFACELESS_MESA,
  EGL_DEFAULT_DISPLAY, NULL)` then a pbuffer surface; read pixels with
  `glReadPixels(GL_RGBA)` and write P6 PPM. If EGL is unavailable, run without
  a renderer and let the screenshot flag print a clear error.
- **Orphaned surfaces.** When a client disconnects, its surface is moved to an
  orphaned-surface list (instead of being freed) so the last-rendered frame
  survives for `--screenshot`. Surfaces render in reverse insertion order
  (`wl_list_for_each_reverse`) so newer surfaces draw on top.
- **Host input (X11).** In windowed mode, `input_process_x11()` processes
  `KeyPress`, `KeyRelease`, `ButtonPress`, `ButtonRelease`, `MotionNotify`,
  `ConfigureNotify`, and `WM_DELETE_WINDOW` on the X11 window. X keycodes are
  translated (minus 8) into the same internal event path used by `--input-script`.
- **SIGCHLD reaping.** A signalfd is added to the Wayland event loop via
  `wl_event_loop_add_fd`. `signalfd_read()` delivers `signalfd_siginfo` records
  that are `waitpid(pid, &status, WNOHANG)`-ed.
- **ASan build.** `meson setup build-asan -Db_sanitize=address,undefined`.
  Leak detection is disabled in test env (`ASAN_OPTIONS=detect_leaks=0`) because
  wayland-server does not free its internal data structures on
  `wl_display_destroy()`. All other ASan checks (use-after-free, buffer overflow,
  etc.) remain active with `halt_on_error=1`.

## Limitations to carry into later handoffs

- xdg-shell is minimal: one fixed 800×600 configure, no `ping`, no `ping`
  timeout, `set_window_geometry`/title/app_id/min/max ignored, no popups.
- Seat multi-bind works but keyboard focus is limited to the most recently
  mapped toplevel only (no explicit focus stealing prevention).
- Launcher works for simple whitespace-split commands; exit status from
  `--launch` errors is logged but not propagated.
- Keyboard layout comes from `XKB_DEFAULT_*` env or `us`; not from the host.
- Host shortcuts grabbed by the host compositor (Steam/KDE) cannot be captured.
- No `weston-terminal` in the container until a person installs `weston`.
- The compositor does not handle `wl_display.destroy` or protocol errors from
  malformed client messages beyond posting standard protocol errors.
- The `MANSION_SOCKET=` line is printed inside the main loop, not after socket
  creation, so clients may race if they connect immediately.
