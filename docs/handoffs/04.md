## Context

P4 builds a single 3D room (10×7×10 box) with furniture (desk, monitor frame)
and demonstrates the complete user journey: start in room mode, walk toward the
monitor, launch a client that appears on the monitor frame, select the panel,
enter application mode, type keys, and return to world mode. A teleport
shortcut (T key) provides reduced-motion access to a stored viewpoint facing
the monitor.

## Architecture

### Room geometry (`src/room.h`, `src/room.cpp`)

The room is a 10×7×10 box with:
- **Floor** (y=0): brown (`#61472c`)
- **Walls** (x=±5, z=±5): grey (`#7f7f8c`)
- **Ceiling** (y=7): grey (`#7f7f8c`)
- **Desk** (x=-3, y=0): dark brown (`#2a1f1a`), 2×1×1.5 box top
- **Monitor frame** (x=0, z=-5, y=2.25..4.5): dark grey (`#3a3a3a`)

All meshes are flat-shaded quads with 5 floats per vertex (x, y, z, u, v).

### Room rendering (`src/display.cpp`)

When `room_mode` is true (set by `--room-camera`):
1. Room meshes are drawn with depth test enabled using `program_3d`.
2. Depth test is disabled, then the panel is drawn on top.
3. The panel in room mode is positioned at (0, 3, -5) — the monitor frame.

The room rendering path uses `program_3d` (the same shader as the regular
3D panel path) with a separate MVP matrix.

### Camera collision (`src/room.cpp::room_apply_collision`)

AABB clamps the camera position:
- x ∈ [-4.5, 4.5] (1 unit padding from walls)
- y ∈ [0.5, 6.5] (floor at y=0, ceiling at y=7)
- z ∈ [-4.5, 4.5] (1 unit padding from walls)

Collision is **only** active when `room_mode` is true. This is gated in
`input.cpp` to prevent non-room tests from being clamped to room bounds.

### Teleport (`src/display.cpp::input_teleport`, `src/input.cpp`)

Key T (evdev 20) teleports the camera to a stored viewpoint:
- Position: (0, 3, 0)
- Yaw: 0, Pitch: 0
- Faces the monitor frame at z=-5

The teleport key is configured via `input_teleport_key_set()` and intercepted
in both World and Application input modes.

### Texture swizzle fix

The test client writes ARGB8888 wl_shm buffers which, on little-endian, produce
RGBA byte order. Mesa EGL surfaceless renderer rearranges GL_RGBA texture storage
to [G, R, B, A]. The fix:
- **EGL mode**: swizzle (data[1], data[0], data[2], data[3]) = (G, R, B, A)
- **Non-EGL mode**: upload RGBA directly (no rearrangement)

Three upload blocks affected: `render_panel()`, `render_surface()`,
`render_application_fullscreen()`.

## Architectural notes

### Room bounds vs non-room tests

Camera collision is gated behind `room_mode` because the room bounds
(x∈[-4.5,4.5], y∈[0.5,6.5], z∈[-4.5,4.5]) would clamp movement in
non-room tests that use different camera ranges. The gate is in
`input_script_apply_movement()` → `apply_movement()` which checks
`display->room_mode`.

### Panel vs monitor frame

In room mode, the panel is positioned at the same coordinates as the
monitor frame (x=0, y=3, z=-5). The room is drawn first with depth test,
then the panel is drawn without depth test on top. This avoids z-fighting
between the panel quad and the monitor frame quad.

### Input script protocol

The `--input-script` format supports:
- `wait N` — wait N milliseconds
- `key CODE press|release` — simulate key event (evdev code)
- `mode world|app` — set input mode
- `motion X Y` — pointer motion
- `button CODE press|release` — pointer button
- `quit` — exit compositor
