# Project 3: world/application input state machine — handoff

Living document for Project 3. Updated in P3-T07 (2026-09-27).

## Context

P3 adds an input state machine with two modes: **World** and **Application**.
In World mode, input drives the camera (clients receive nothing). In Application
mode, input goes to the focused surface. A configurable host shortcut (default
F12) returns to World mode. Panels are targeted via raycasting; Enter on a
targeted panel enters Application mode. In Application mode the focused surface
is presented full-size.

## Host shortcuts that cannot be captured

These shortcuts are intercepted by the host compositor **before** they reach
any Wayland client. A client in Application mode cannot capture them.

| Shortcut | Default key | Action |
| --- | --- | --- |
| World exit | F12 (evdev code 88) | Returns to World mode, releases all held keys, sends keyboard/pointer leave |

The world key is configurable via `--world-key <evdev-code>` on the command
line.

**Why they cannot be captured:** The compositor processes the world key in
`input_process_x11()` before dispatching key events to any Wayland seat client.
X11 grabs (if used) or early filtering in the input pipeline ensures the host
always sees the shortcut. This is the correct design — a full-screen application
must never be able to prevent the user from exiting.

## Architectural notes

### Dual-link fix (P3-T06)

`SeatKeyboardClient` and `SeatPointerClient` each own **two** list elements:

- `destroy_listener.link` — linked into the Wayland resource's `destroy_signal`.
  Used exclusively by libwayland during resource teardown.
- `seat_link` — linked into `seat->pointer_clients` / `seat->keyboard_clients`.
  Used exclusively by the compositor for iterating active clients.

These must **not** share the same `wl_list` element. `wl_list_insert` overwrites
`prev`/`next` pointers; inserting the same element into two different lists via
separate `wl_list_insert` calls corrupts the first list. This was the root cause
of the P3-T06 crash.

### Focus clearing (P3-T06)

`seat_clear_focus_state()` sets `g_seat->focused_surface_resource` and
`g_seat->pointer_surface_resource` to `nullptr`. Called from
`surface_destroy_callback` when the focused surface is destroyed, to prevent
dangling pointers. If the focused surface disappears while in Application mode,
the mode is also reset to World (to avoid sending events to a non-existent
focused client).

### SIGSEGV handler (P3-T06)

A `sigaction(SIGSEGV)` handler in `main.cpp` dumps registers (RIP, RAX, RDI,
RSI, RBX, RSP) and a 64-value memory dump around `si_addr` before calling
`_exit(139)`. Useful for diagnosing future crashes in the Wayland teardown
sequence.

## Gate A decision (2026-09-27)

**Continue with the current world/application input state machine.**

Rationale:
- All 20 tests pass (`meson test -C build --print-errorlogs`).
- The two-mode input model is clean: World drives the camera, Application
  drives the focused surface.
- The world key shortcut is reliably intercepted before reaching clients.
- Client exit during Application mode is handled correctly (no crash).
- Full-size presentation and panel targeting work end-to-end.
- Cross-client pointer safety is enforced in `exit_application_mode()` and
  `seat_set_keyboard_focus()`.

Open issues:
- Windowed mode (X11) has not been observed — requires a DISPLAY session.
- The world key shortcut is a single key; no multi-key shortcuts (e.g.,
  Ctrl+Shift+F12) are supported yet.
- `seat_clear_focus_state()` only clears surface pointers, not the stored
  `focused_surface_resource` on `MansionCompositor`. Both are set to nullptr
  in `surface_destroy_callback`.
