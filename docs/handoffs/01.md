# Project 1: Nested compositor foundation - handoff

## Context

This is the initial handoff. No code has been written yet due to missing development dependencies.

## Next task

Implement a minimal nested compositor that can launch and display a Wayland terminal.

## Prerequisites

Set up the development environment following [DEVELOPMENT.md](../DEVELOPMENT.md) or use the Docker container.

## Detailed requirements

1. Create a Wayland compositor that:
   - Listens on a Wayland socket (e.g., `mansion-desktop socket`) 
   - Implements required protocols: `wl_compositor`, `wl_shell`, `xlkgb`
   - Creates a single-output EGL/GLES2 renderer
   - Handles keyboard and mouse input
   - Maps surfaces as wl_shuwm shells
   - Responds to surface commits
   - Handles surface resize and close
- See [IMPLEMENTATION-GUIDE.md](../IMPLEMENTATION-GUIDE.md) for technical details
- Consider using wlroots to accelerate development (but not required)

2. Create a launcher that:
   - Sets up necessary environment variables (`WAYLAND_DISPLAY`, `XDG_RUNTIME_DIR`) 
   - Launches `weston-terminal` (or another simple Wayland terminal) on the compositor's socket
   - Can launch arbitrary commands via a `--launch` argument

3. Verify:
   - Terminal starts and displays
   - Typing works
   - Resizing works
   - Closing the terminal exits cleanly
   - Host desktop remains usable after Mansion Desktop exits

## Implementation notes

- Use the Wayland C API (header `<wayland-server.h>`)
- Use EGL for OpenGL rendering
- Use xkbcommon for keyboard handling
- Implement proper error handling and cleanup
- Start with 2D rendering - no 3D yet
