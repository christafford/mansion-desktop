## Context

P2 adds a 3D perspective panel: a camera views a panel plane onto which the
compositor projects a client surface as an OpenGL texture. Supports
`--flat` (2D path) and `--camera X,Y,Z,YAW,PITCH` for 3D mode.

## P2-T07 measured numbers

Machine: Steam Deck, AMD Custom GPU 0405 (vangogh), radeonsi/vangogh, Mesa 26.2.

Headless, `--camera 0,0,10,0,0 --stats`:

```
stats: 60 frames, ~74000 fps, 0 KiB uploaded
```

With a 200×200 red client running (`--launch "… --buffer 200x200 --color ff0000"`):

```
stats: 60 frames, ~7361 fps, 9062.5 KiB uploaded
```

With a 200×100 client (default size):

```
stats: 60 frames, ~70000 fps, ~4500 KiB uploaded
```

Interpretation: upload bandwidth scales with surface area (200×200×4 = 160 KB/frame).
At 60 fps that is ~9.6 MiB/s per surface. FPS varies by whether clients are
connected (more rendering work) and by system load. Headless path with no clients
is effectively unbounded by rendering.

## Gate A decision (2026-09-27)

**Continue with the current renderer/compositor integration.**

Rationale:
- All 14 tests pass (`meson test -C build --print-errorlogs`).
- The EGL surfaceless Mesa renderer works reliably for headless testing.
- The swizzle workaround (R←G, G←B, B←R, A←A) is documented and stable.
- `--input-script` and `--report-input` provide deterministic test automation.
- Texture lifetime management is correct (create/resize/delete + GL error check).
- Camera movement, mouse look, and frame timing stats all work.
- P2-T05 EGL experiment confirmed zero-copy import is **not** available on this
  hardware (`EGL_WL_bind_wayland_display` and `eglCreateImageKHR` symbols are
  all NULL), so the shm export path is the correct approach.

Open issues:
- Windowed mode (X11) has not been observed — requires a DISPLAY session.
- `--stats` overhead is minimal (one `steady_clock` + two additions per frame)
  but only useful in debug/development builds.
- `MansionRenderer::bytes_uploaded` is not reset between frames — it only resets
  after a stats print (every 60 frames). This is intentional to avoid per-frame
  overhead; the counter wraps at `LLONG_MAX` which would take ~3000 years at
  1 GiB/s.
